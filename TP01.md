## Chapter 1: Clean Code, PEP 8, and Debugging

In this chapter, we learn how to write clean, readable, and maintainable code by following coding conventions and using effective debugging techniques. The main topics include Clean Code principles, Python's PEP 8 style guide, and debugging tools.

### 1. Clean Code

Clean Code refers to writing code that is easy to read, understand, maintain, and improve. Good code should allow other developers to follow the program's logic without unnecessary confusion.

#### 1.1. Naming Conventions

We learn the basic principles of naming different elements in a Python project, including:

- **Modules and files:** Use clear, descriptive names, usually written in `snake_case`.
- **Functions and variables:** Use meaningful names that describe their purpose, such as `calculate_total()` or `student_name`.
- **Classes:** Use `PascalCase`, such as `StudentManager` or `BankAccount`.
- **Constants:** Use uppercase letters with underscores, such as `MAX_RETRIES` or `DEFAULT_TIMEOUT`.

During the class, my activity is to explain to my classmates how to write clean and readable Python code when working with Object-Oriented Programming (OOP), especially when defining classes, attributes, methods, and objects.

#### 1.2. Code Comments and Documentation

We learn how and when to write comments to make code easier to understand.

The main types include:

- **Inline comments:** Brief explanations placed on the same line as a statement, when necessary.
- **Block comments:** Explanations written above a section of code to clarify its purpose or logic.
- **Docstrings:** Documentation written inside modules, classes, and functions to describe their purpose, parameters, and return values.

We also learn that comments should explain *why* something is done when the reason is not obvious, rather than simply repeating what the code already says. Comments should be updated whenever the related code changes.

### 2. PEP 8: Python Coding Style Guide

PEP 8 is the official Python style guide. It provides conventions that help developers write consistent, readable, and well-organized Python code.

In this section, we learn the main principles of PEP 8 and how to apply them when writing Python programs.

#### 2.1. Code Formatting

We learn how to format Python code correctly, including:

- Using four spaces for each indentation level.
- Keeping lines within the recommended line-length limit.
- Adding appropriate blank lines to separate functions and classes.
- Using spaces around operators, such as `=`, `+`, and `==`.
- Organizing imports clearly at the beginning of a file.

#### 2.2. Following Naming Conventions

PEP 8 also defines naming conventions for different elements of Python code. We learn to use consistent naming styles for variables, functions, classes, constants, and modules.

Following these conventions makes code easier for other developers to read and understand.

#### 2.3. Writing Consistent and Readable Code

We learn that following PEP 8 is not only about making code look neat. It also helps create consistency across a project, making collaboration, code reviews, and maintenance easier.

### 3. Debugging

Debugging is the process of identifying, analyzing, and fixing errors in a program.

In this section, we learn different ways to investigate problems in our code and understand why a program does not behave as expected.

#### 3.1. Using Print Statements

One simple debugging technique is to use `print()` in Python to display variable values, check the execution flow, and identify where an error may occur.

For example:

```python
def calculate_total(price, quantity):
    print("Price:", price)
    print("Quantity:", quantity)

    total = price * quantity
    print("Total:", total)

    return total
```

This approach is useful for simple debugging tasks. However, adding too many print statements can make the code harder to maintain.

#### 3.2. Using Debugging Tools

We also learn that dedicated debugging tools can help us investigate problems more efficiently than relying only on print statements.

For example, debugging features in an IDE or code editor can help us:

- Set breakpoints to pause program execution.
- Execute code step by step.
- Inspect variables and their values.
- Follow the program's execution flow.
- Identify the source of errors more quickly.

Language Server Protocol (LSP) tools improve editor support by providing features such as code navigation, diagnostics, and code completion. Actual debugging is generally handled by a debugger integrated with the editor or IDE, rather than by LSP itself.

### 4. Tips and Tricks for Following PEP 8

In this section, we explore practical ways to ensure that our Python code follows PEP 8 conventions.

Some useful practices include:

- **Use a consistent naming style:** Follow `snake_case` for functions and variables, `PascalCase` for classes, and uppercase names for constants.
- **Configure the code editor:** Enable Python formatting and linting features to identify style issues while writing code.
- **Use automated tools:** Tools such as `Ruff` and `Flake8` can check code for style violations and other potential problems.
- **Format code automatically:** Use a formatter such as `Black` or Ruff's formatter to maintain consistent formatting.
- **Review code regularly:** Check indentation, spacing, imports, naming conventions, and comments before submitting your work.
- **Practice collaborative code reviews:** Ask classmates to review your code, discuss possible improvements, and correct mistakes together.

By applying these techniques, we can reduce common style issues, improve code readability, and develop good programming habits.
